# CONTRACTS.md — cross-module data contracts

Source of truth: backend Pydantic models. `frontend/src/types.ts` mirrors them and must change in lockstep. All changes are additive; removals need a user decision.

## DatasetProfile — `profiling/models.py` L:413
- Producer: `profile_dataset` (`profiling/profiler.py`), cached by `ProfileService`, keyed by dataset id, invalidated when `PROFILE_VERSION` (now 10) changes.
- Consumers: `charts/rules.py`, `charts/render.py`, `charts/spec.py` (validation), `llm/*`, `probes/*`, router `/profile`, frontend Overview/Explore.
- Fields: `profile_version, dataset_id, n_rows, n_cols, sampled, profiled_rows, columns[ColumnProfile], correlations, evidence, sample_rows(≤5)`.
- `ColumnProfile.categories` (stage 19.2, `PROFILE_VERSION` 14, optional): every distinct label as str, sorted, when a categorical / boolean column has ≤ `CATEGORY_LABELS_MAX` 13 categories — the input of semantic-role detection (`charts/roles.py`), so twelve month names are a cycle although `top_values` keeps the 10 most frequent; None above the cap.
- Invariants: every statistic was computed on `profiled_rows` rows (== `n_rows` unless sampled >100k); `sample_rows` is the only raw data anywhere downstream; `semantic_type ∈ numeric|categorical|datetime|boolean|text|id|unknown`; `nominal=True` categoricals are never a numeric y; `quality` carries sentinels/robust range/invalid counts and never mutates the stored data.

## Evidence — `profiling/models.py` L:401 (+ `EvidenceLayer2` L:391)
- Producer: `compute_evidence` (L1) and `compute_layer2` (L2), both deterministic Polars.
- Consumers: L1 → `rules.py` scoring, `evaluate_llm_spec`, prompts, probes. L2 → prompts and probes only (rules never read L2).
- L1: `cat_num[CatNumEffect(adjusted eta², n_total, n_min, group_counts)]`, `time_effects`, `num_num_spearman`, `interactions`, `slope_heterogeneity`, `derived_columns` (row-wise identities like `a×b×(1−c)`; ≥99% match; stage 19.2 adds kind `bucket`: a categorical whose groups are ordered, disjoint, contiguous ranges of a numeric column — `band = bucket(price)` — detected in the dispersion pass, formula `bucket(<num>)`, match_ratio 1.0, treated by every consumer like an identity), `near_duplicate_groups` (|ρ|≥0.995, or ≥0.98 with related names; representative column chosen), `dispersion[DispersionEffect]` (stage 19.1 / 19.2: spread differences of `num` across `cat`, independent of the mean difference — Brown–Forsythe adjusted η² of |x − group median| `bf_eta_squared`, the F statistic `bf_f` and its p-value `bf_p_value` (F survival via the regularised incomplete beta, pure Python), `std_ratio / iqr_ratio / mad_ratio`, the robust `spread_ratio` with `widest_group / narrowest_group`; `compared_groups` / `excluded_groups` (label → rows) say which groups the comparison ran over — with ≥ 2 groups of ≥ 30 rows exactly those are compared first and smaller groups are excluded; when that lists nothing, every group ≥ 10 rows is compared at most weak; a group without any value of `num` is excluded with 0 rows; `n_groups / n_total / n_min` describe the compared groups; `strength` strong needs the supported comparison plus p ≤ `DISPERSION_ALPHA` 0.05, weak needs p ≤ 0.10; effect gates η² ≥ 0.02 and ratio ≥ 1.5 always; `definitional / definitional_kind / definition` flag entries that restate an identity, near copy (also through a chain: `num` a near copy of a column derived from `cat`) or banding — kept, never a headline)
- Consumers of `dispersion`: `rules.py` (`_EvidenceIndex.spread_differs` = strong AND non-definitional entries → `distribution_by_group` intent), `llm/prompts.py` ("Spread differences" lines, with the compared / excluded groups and a DEFINITIONAL note). It is the only L1 table the rules read for spread; `layer2.group_summaries` is LLM-only again.
- Invariants: derived pairs are "definitional, not a finding" (score ×0.6, tier cap exploratory, warning); near-duplicate non-representatives are excluded from candidates (heatmap keeps all); every effect carries the n it was computed on; a small sample never yields a strong dispersion entry.

## ChartSpec — `charts/spec.py` L:28
- Producers: rules engine, LLM (via canonicalize + `validate_spec`), manual builder (frontend), fixtures.
- Consumers: `render_chart`, `Recommendation.spec`, frontend preview/workspace (`specKey` identity).
- Fields: `title, type, x, y, group_by, aggregation, bins(histogram), time_granularity(line+datetime x), top_n(bar/lollipop; default 20), sort(natural|value|null; stage 19), reason, priority`.
- Types (stage 19): the six originals `line|bar|scatter|histogram|box|heatmap` plus `violin|raincloud|ridgeline` (density per category, x optional for violin), `dot_interval` (mean ± 95 % per category), `lollipop` (bar payload), `dumbbell|slopegraph` (x category × `group_by` with exactly 2 states → aggregate of y), `hexbin` (numeric × numeric counts), `polar_line|rose` (aggregate around a **cyclic** x — `column_role(x).cyclic`, never a nominal column). `line` also accepts an ordered categorical x (cyclic / ordinal role) with an aggregation. `heatmap` with no fields = correlation matrix; with `x + group_by + y + aggregation` = matrix pattern.
- `sort`: category order on a category axis — `natural` (the role's own order: month 1..12, Mon..Sun, low..high), `value` (ranked by the aggregate; only the `ranking` intent asks for it), `null` = ordered roles natural, nominal ranked (bar) / alphabetical (box family).
- Invariants: `validate_spec(spec, profile)` is the only gate; errors return 422 `{detail:{errors:[…]}}`; no pie; bar never on high-cardinality categoricals; column roles must match semantic types; the type says how a chart is drawn, the intent (below) why it was chosen.

## Recommendation — `charts/rules.py` L:54
- Producer: `recommend_charts` → caps → `apply_confidence` → `assign_tiers` (rules); `RecommendationService` for merged LLM output.
- Consumers: router `/recommendations`, frontend Insights/Preview.
- Fields: `spec, score, source(rules|llm), tier(top|secondary|exploratory), confidence{sample_size, missingness, robustness, overall, n_total, n_effective, missing_ratio, min_group_n, n_source}, warnings[{code, severity, message, meta}]`, `intent` (stage 19: `trend|distribution|distribution_by_group|group_comparison|ranking|numeric_relationship|cyclic_pattern|matrix_pattern|two_state_comparison|composition|flow`, null for the correlation heatmap), `alternatives: ChartSpec[]` (the other eligible charts of the same finding, validated; the UI shows the preferred `spec` and offers these); `tier_cap` internal only (excluded from JSON).
- Stage 19 pipeline: `charts/roles.py` (semantic role per column: numeric / datetime / boolean / nominal / ordinal / cyclic, deterministic from the profile) → `charts/intent.py` (`classify_intent(x, y, group, ctx)` → `select_chart(intent, …, hint)` with named guards: density ≥ 30 rows per group, raincloud ≤ 6 groups, ridgeline 3–12 ordered groups, hexbin > 5000 rows, polar period ≤ 24 & ≥ 4 categories, rose only with a sum/count magnitude, dumbbell exactly 2 states, slopegraph ≤ 8 categories) → one `Recommendation` per (x, y, group) finding. LLM- and probe-suggested charts pass through `select_for_spec`: their type is a hint, never an inventory the LLM must know.
- Invariants: `score = base × confidence.overall` (base recoverable); tiers are score-based with a 0.68 top floor, decoupled from display order; diversity caps per family (intent) ≤3, per-x ≤2 (cyclic lines included, trend lines exempt), per-y ≤3; stage 19.1: within those caps the `MAX_CHARTS` slots are filled by slot value = `score × QUESTION_DECAY^(kept answers to the same (intent, x, group_by) question) × TYPE_DECAY^(kept charts of the same raw type beyond TYPE_FREE_SLOTS)` (0.8 / 0.85 / 2) — membership only, the list stays score-ordered, scores and tiers unchanged, idempotent (the LLM merge re-caps); a rec with `tier_cap` never exceeds it; sentinel-sensitive aggregations (mean/sum/min/max) are discounted, median/count are not; `?llm=false` output is a pure function of the profile (snapshot md5 changes only with a rules change — stage 19: `see CURRENT_STATE.md (re-recorded on every rules change)`).

## Insight / RecommendationsResponse — `llm/service.py` `get()`
- Producer: `RecommendationService.get(profile, use_llm)`.
- Consumers: router, frontend Insights page.
- Shape: `{charts: Recommendation[], insights: [{text, supported(strong|weak|unverified; backend-internal "neutral" is shown as weak), chart_priority|null, headline|null, why_it_matters|null, validation(existing_evidence|probe), priority(1..5), effect{label, value, n}}], message|null, warnings: Warning[]}`. `headline` (stage 18) is LLM #2's short number-free claim, gated by the same wording check as `text` and dropped (null, never truncated) on any problem or > 120 chars; the frontend shows `text` when it is null. Presentation only: no statistic depends on it.
- Invariants: with `use_llm=False` the output is a pure function of the profile (byte-identical across LLM changes); weak insights never make top; an insight's chart must pass `validate_spec` or `chart_priority` is null; `message` explains an empty result honestly; dataset-level warnings disclose excluded columns (`MAX_MISSING_RATIO`), derived and near-duplicate columns.

## RenderResult — `charts/render.py` L:50 → frontend `types.ts` L:211
- Producer: `render_chart(df, spec, profile)` via `POST /api/charts/render {dataset_id, ...spec}`.
- Consumers: `buildOption` (frontend), fixtures in `frontend/src/charts/__fixtures__/`.
- Shape: `{spec, chart_data, sampled, n_points, display_range|null}`; `chart_data` per type: line/scatter `{series[{name, x, y}], y_label}`, bar / lollipop / polar_line / rose `{categories, series[{name, values}], truncated, y_label}`, histogram `{bins{edges, counts}, series?, y_label}`, box `{groups[{name, q1, median, q3, lower_fence, upper_fence, outliers, mean, count}], y_label}`, heatmap `{columns, matrix(−1..1, null allowed), y_label}` or matrix pattern `{columns, rows, matrix, y_label}`; stage 19: violin / raincloud / ridgeline `{groups[{…box stats, density[64] (peak 1), bandwidth, points?[≤200]}], grid[64], y_label}`, dot_interval `{groups[{name, mean, lo, hi, n}], y_label}` (1.96·sd/√n, null below n=2), dumbbell / slopegraph `{categories, states[2], series[{name, values}], y_label}`, hexbin `{cells[[col, row, count]], x_range, y_range, dx, dy, columns, rows, n, y_label}`.
- Invariants: category order is backend order — natural for ordered roles or `sort=natural`, ranked for `sort=value` / nominal bars, alphabetical for nominal box-family groups; nulls are gaps, never zeros; histogram binned over robust range with `display_range` disclosing excluded rows (`sum(counts)+excluded == valid rows`); `y_label` alone drives the axis title; `HARD_MAX_POINTS` → `RenderError` (422), scatter sampled with `sampled=true`.

## ProbeRequest / ProbeResult — `probes/schemas.py` L:49 / L:70
- Producer: LLM workflow `llm/service.py` (`_Workflow`, stage 17.3); engine `run_probes`.
- Shape: request `{type, columns{role: name}}` with `extra="forbid"`; result `{type, columns, effect_size, effect_label, n, n_min_group, confidence, verdict(pass|weak|fail), thresholds{pass, weak}, evidence(structured only), chart|null, notes, cached}`; rejected `{type, columns, reason, rejected: true}`.
- Invariants: never returns raw rows; thresholds come from the engine, LLM-stated numbers are ignored; ≤5 probes per dataset; cache key = (type, sorted columns).

## HTTP API — `datasets/router.py`
`GET /api/health` · `POST /api/datasets` (multipart) → `DatasetMeta` · `GET /api/datasets` · `GET /api/datasets/{id}` · `/preview` · `/profile` → DatasetProfile + `column_roles: ColumnRole[]` (stage 19.1, additive, response-only: `charts/roles.py` roles `{name, role, ordered, cyclic, period, order, n_categories, two_state}` computed at response time — the cached profile and the profiler never carry them; `frontend/src/types.ts` mirrors it as `DatasetProfile.column_roles?`) · `/recommendations?llm=true|false&debug=0|1` → RecommendationsResponse (`debug=1` adds the optional `debug` workflow trace) · `POST /api/charts/render` → RenderResult. Errors: 404 unknown id, 422 `{detail:{errors}}` for spec/loader problems.
